# Iteration 003 feedback

## Outcome

Completes the user-requested stable delivery block: predictable failures, a small offline example, reproducible verification, clear startup documentation, and synchronized v0.3.0 stage versions.

## Changes

- Shared manifest/tag validation and clean CLI cancellation. Invalid responses and downloads now offer actionable UI messages.
- Three fixed synthetic features generated by `uas-planner sample`; original user datasets are never overwritten.
- Real API/browser test checks all exports, including binary GeoPackage checksum, using independent ports and no map services.
- README quick start and troubleshooting address observed port conflicts and the distinction between frontend port 5173 and backend port 8000.
- Version agreement is checked automatically; changelog and locked dependencies describe the release baseline.

## Validation and lessons

Error regressions and the real-stack sample complement the earlier mocked UI tests. Local pre-release checks pass; final counts and remote integration evidence are recorded after sprint verification. Existing Braunschweig data is retained locally and remains excluded from Git.

GeoPackage edits should use geospatial tooling: a test fixture initially attempted plain SQLite updates but GeoPackage spatial triggers require spatial functions. Rewriting its test layer through GeoPandas provided the intended corrupt-tag fixture.

Synthetic data must not be presented as surveyed OpenStreetMap data. The sample marks its provenance in storage, API, and UI. Stable feature content does not imply identical file bytes because saves record timestamps.

## Limits and next discussion

Small-area, in-memory processing and CLI-only acquisition remain deliberate limits. The Starlette/httpx deprecation warning remains a dependency follow-up; no package upgrade was needed for this release. Windows symlink testing depends on OS privileges and is exercised in Linux CI. No next sprint is approved.
